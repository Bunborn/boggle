Fixed a confirmed out-of-bounds bug in fillBoard() and printBoard() today — both functions had the outer and inner loop variables swapped relative to how buildBoard() allocates memory. buildBoard() allocates cubes[rows][cols] (rows outer arrays, each cols wide), but both fill and print were iterating cols as the outer index and indexing cubes[col][row], which writes past the end of the outer array on any non-square board where cols > rows. The fix was straightforward: rename the loop variables to row/col in fillBoard() and swap the i/j bindings in printBoard() so the outer loop walks rows and the inner walks cols, with all array accesses following cubes[row][col]. Also corrected both border-drawing loops in printBoard() to use gameBoard->cols for the width (since borders span across columns, not rows). This was invisible on square boards — which is exactly why it survived until now. Flagging for the team: any future board sizing that allows non-square configs should have a targeted test case for the non-square layout to catch this class of bug early.
